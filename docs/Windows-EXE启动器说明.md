# Agent Studio 1.2.1 · Windows EXE 启动器

## 1.2.1 启动兼容修复

旧版错误引用了 Mono 运行库额外提供的三个字符串重载，Windows Framework 入口 JIT 抛出 MissingMethodException，无法进入原错误捕获。现采用 Framework 4.8 参考程序集编译并显式使用字符数组重载；新增独立 Bootstrap、不可内联的 GUI 入口以及原生错误弹窗。包内包括 `Agent Studio.exe.config` 指定 Framework 4.8 运行目标。

所有 266 个方法／字段引用对目标参考程序集解析为零缺失；旧版同一审计检出 3 处缺失。Linux/Mono 下入口兼容探针成功，模拟无显示环境的 UI 初始化失败时能提前生成完整日志。这不等同于 Windows 桌面实测。

窗口创建前日志为 `data/launcher/bootstrap-*.log`；目录不可写则依次尝试 `%LOCALAPPDATA%/AgentStudio/launcher` 和系统临时目录。操作系统在托管入口执行前直接阻止文件加载时，仍需查看 Windows 事件日志。

## 日常使用

1. **首次从旧 BAT 版升级**：先关闭旧的服务窗口，备份 `data`，完整解压并覆盖原项目目录，保留 `data`。
2. 双击根目录 **`Agent Studio.exe`**。不要从 ZIP 预览中直接运行，也不要只复制 EXE 到别处。
3. 启动进度窗口依次显示环境检查、旧实例处理、依赖检查／安装、前端构建、后台启动和浏览器打开。进度条为不定时滚动条，表示当前阶段正在进行，不伪造下载百分比。
4. 优先使用 Microsoft Edge，找不到时使用 Google Chrome，以 `--app` 模式打开独立窗口。
5. 检测到本次浏览器的可见窗口后，启动进度自动隐藏。关闭本应用的全部浏览器窗口后，启动器自动保存数据并清理本次后台进程。

应用本体仍然是 **Node.js 服务 + 浏览器页面**，不是 Electron。EXE 是真实的 Windows GUI 子系统程序（x64/.NET Framework），不是伪装扩展名的 BAT，也不是只把 BAT 隐藏起来运行。

## 重复双击与重新启动

- **正在启动时再次双击**：通过按项目目录命名的互斥锁和事件通知原启动器，唤回进度窗口，不会重复安装、构建或启动 Node。
- **已经运行时再次双击**：通知原启动器关闭自己的应用窗口和服务，再重新启动。关闭阶段的重复点击不再安排额外重启。
- 同目录同 Windows 会话中的 EXE 实例会协调运行。不同目录的项目不混用实例锁。
- 新版服务还提供仅本机可用的身份／关闭接口，用项目根目录、实例 ID 和 PID 判断是否为本目录旧实例。先正常保存并关闭；仍未退出时，仅在重新核实身份后尝试结束其进程树。
- **不会按 `node.exe`、`msedge.exe`、`chrome.exe` 名称全局杀进程**，不会结束其他项目或日常浏览器。
- 端口被不明程序占用、另一个目录的 Agent Studio 占用，或旧版本不支持身份确认时，会提示用户处理，不冒险杀进程。1.1.x 及更早 BAT 版首次升级需手动关闭一次。

默认端口 3000，浏览器固定访问本机 IPv4 回环地址，避免 localhost 解析到其他 IPv6 监听者。修改端口前请先退出当前应用。如有需要，可在 Windows 快捷方式的目标中添加参数：

```text
"D:\hermes\agent-studio\Agent Studio.exe" --port 3001
```

## 后台进程与退出

- Node、npm、构建命令在隐藏窗口模式下运行，标准输出／错误写入日志，不弹出 CMD 或 PowerShell 控制台。
- Windows Job Object 分别管理本次服务进程树和浏览器进程树，采用 **挂起创建 → 加入 Job → 恢复运行**，避免先运行再追踪进程的竞态。
- Job 设置 `KILL_ON_JOB_CLOSE`。正常退出会先请求服务保存数据、关闭 MCP／CLI 会话并关闭浏览器窗口，再清理剩余进程；启动器意外结束时，Windows 会清理仍在所属 Job 内的进程。
- npm／Node 子进程使用 GUI 专用预加载脚本，将常见子进程调用设为隐藏窗口，并保留正常参数和回调。普通 BAT／命令行启动不加载该脚本。
- 启动期间点击「取消启动」或关闭进度窗口，同样清理本次启动的进程。
- 如果浏览器窗口未出现、后台意外退出或安装构建失败，会弹窗说明并提供日志入口，不留下一个无限等待的进度条。
- 浏览器使用独立的 `data/desktop-browser/` 用户目录，不使用日常浏览器的默认配置。应用打开的新窗口或开发者工具也属于这一组；全部关闭后退出。

**边界**：Job 可控制继承其归属的本地进程；不能撤销工具已经产生的副作用，不能控制第三方工具启动的系统服务、计划任务或远程任务。查看日志时由用户打开的记事本窗口不属于应用进程树，不会被自动结束。GUI 模式建议使用应用内置终端，不依赖外置命令行窗口。

## 环境、网络与证书

- Windows 10/11 **x64**；推荐 .NET Framework 4.8，Node.js 24 LTS。Node 最低版本仍为 20.19；部分 CLI 有更高要求。
- 必须已安装 Edge 或 Chrome。企业策略禁止 APP 模式／自定义用户目录时，可能无法启动专属窗口，会明确报错。
- 不内置 Node 和 npm 依赖，不是完全离线单文件 EXE。首次安装、依赖变化时仍需要可用网络；每次启动重新构建前端，确保覆盖后是新版本。
- 安装阶段仍自动读取 Windows 系统代理。不会永久修改系统代理或用户 `.npmrc`。
- 支持 `--use-system-ca` 的 Node 版本会启用系统受信任证书；在本次启动的子进程中移除 `NODE_TLS_REJECT_UNAUTHORIZED=0` 并启用 npm 严格证书验证，不修改用户全局环境。
- 显式 npm `ca`／`cafile` 可能覆盖默认信任。公司 CA 未正确安装、代理需要集成认证或不同域名 PAC 规则不同，仍可能导致下载失败；此时检查日志并联系企业 IT，**不要关闭证书验证**。
- EXE **尚未进行代码签名**。SmartScreen 或企业安全策略可能提示／拦截，需要按组织规定审批或签名；不建议关闭安全软件。

## 日志与原项目数据

- `data/launcher/<时间>-<标识>.log`：启动器阶段和错误日志。
- `data/launcher/<时间>-<标识>-process.log`：Node、npm、构建和浏览器进程输出。
- 进度窗口及失败对话框提供日志入口。日志可能包含路径、服务错误等隐私内容，分享前请检查敏感信息。
- 保留原 `data/db.json`、资料、密钥和会话。浏览器专属用户目录可以重新生成，但不要将整个 `data` 当缓存删除。
- `start.bat` 保留作诊断备用；它仍会显示控制台，且不提供 EXE 的完整窗口生命周期。日常应使用 EXE。

### 建议 Windows 实机验收

1. 双击 EXE，确认只有进度窗口，无命令行窗口。
2. 启动时连续双击数次，确认只有一次安装／构建和一个进度窗口。
3. 浏览器 APP 窗口出现后，确认进度窗口及时消失。
4. 已运行时再次双击，确认旧应用关闭后新窗口出现，版本为 `1.2.1 / windows-bootstrap-r2`。
5. 正常关闭应用窗口，确认所属 Node／浏览器进程退出，普通浏览器仍然可用。
6. 安装阶段取消、端口被其他程序占用、无浏览器、企业证书错误，确认均有明确提示和日志，不误杀其他进程。
7. 使用带空格、中文的目录进行一次安装及重启验证。

## 源码与重编译

源码位于 `launcher/Launcher.cs`、`launcher/NativeJob.cs`，资源为 `launcher/app.manifest` 与图标。Windows 环境可用 `launcher/build.ps1` 编译（需要系统提供 .NET Framework C# 编译器）。使用源码编译并不需要 Electron、WebView2 SDK 或额外 npm 包。


Linux 交叉编译请使用 `sh launcher/build-mono.sh`，其显式引用 Framework 4.8 API DLL 并禁用默认标准库引用，禁止退回 Mono 运行库 API。可用 `launcher/VerifyFrameworkApi.cs`（构建工具依赖 Mono.Cecil）对 EXE 的全部外部成员引用进行审计。不要用不指定目标参考程序集的裸 `mcs` 命令重新编译。
