# Agent Studio 1.1.0 · 知识库与 MCP

构建标识：`knowledge-mcp-r1`。在原项目上增量更新，保留原有四个模块、六种 CLI 智能体、网络代理、终端中文输入修复，以及助手下的二级话题列表。仍然是 Node.js + 浏览器，不是 Electron。

本轮实现知识库与 MCP 的核心闭环，不代表 Cherry Studio 的全部资源功能已 1:1 完成。未复制 Cherry Studio 源码。行为参考项目：<https://github.com/CherryHQ/cherry-studio>；协议使用官方 MCP SDK：<https://github.com/modelcontextprotocol/typescript-sdk>。

## 一、先正确覆盖升级

1. 停止旧服务，先备份整个 `data` 文件夹。
2. 将 ZIP 完整解压，覆盖**原来的项目根目录**，不要套进另一层同名目录。保留自己的 `data`。
3. 双击 `start.bat`。本轮新增了依赖，启动器会根据 package/lock 指纹检查并安装，而不是只看 `node_modules` 是否存在；然后重新构建前端。
4. 启动器只在健康检查确认是本次启动的实例后自动打开浏览器，避免误开占用端口的旧实例。
5. 必要时浏览器按 Ctrl+F5。访问 `/api/health` 应看到 `version: 1.1.0`、`build: knowledge-mcp-r1`；导航栏版本提示应一致。

Node.js 至少 **20.19**，推荐当前 **24 LTS**；具体 CLI 可能要求更高版本。压缩包含最新生产前端、源码、锁文件和逐文件 SHA-256 清单，不含用户数据、密钥和已安装依赖。

## 二、知识库：从资料到带来源的回答

1. 左侧进入「知识库」，新建一个库。
2. 初次建议选择**本地关键词**，不需要 Embedding 服务或额外密钥。
3. 导入 PDF、DOCX、MD 或 TXT，等待资料状态变为「可检索」。失败时会显示原因，可以重试；已有资料可以重新索引、删除。
4. 在库详情里先用「检索」验证能否找到所需片段。
5. 编辑智能助手 →「知识库与工具」→ 绑定一个或多个库 → 保存。
6. 回到该助手的话题里提问。聊天顶部显示启用的资源数量，回答下方可展开来源，包含文件名、PDF 页码（适用时）、片段编号、文本和索引时间。

来源列表表示**本轮实际检索并提供给模型的内容**，不是对模型每句话正确性的认证。模型是否按 `[来源N]` 标注仍取决于模型；请核对原文。来源是对话快照，删除原资料会立即影响后续检索，但不会自动抹去历史消息中的片段。删除整个库同时解除助手绑定。

### 可选：Embedding 混合检索

在「模型服务」配置并启用兼容 OpenAI `/v1/embeddings` 的服务商；新建库时选择向量模式、服务商和实际可用的 Embedding 模型 ID。聊天模型和 Embedding 模型不是同一个概念，普通聊天模型不一定支持该接口。

- 索引时资料片段会发给选定的 Embedding 服务；检索时问题也会发送，可能产生费用。
- 命中的片段随后会随聊天请求发给当前聊天模型。本地关键词模式只是不调用 Embedding，**不代表使用远程聊天模型时资料始终留在本机**。
- 遵循应用的模型出站代理设置，使用对应服务商的密钥及自定义请求头。
- 模式与 Embedding 模型创建后固定；要切换请另建库。服务商地址或类型变更后，旧向量需要重新索引；系统会拒绝混用不同指纹／维度的向量。
- 当前为关键词 + 向量的轻量混合检索，**没有 Rerank**，不声称与专业向量数据库等价。

### 格式和容量边界

| 项目 | 当前限制 |
| --- | --- |
| 格式 | PDF、DOCX、UTF-8 TXT／MD；不支持旧 `.doc` |
| 单文件 | 20 MB；提取文字 20 万字符；最多 300 个片段 |
| PDF | 最多 150 页，超限明确报错；依赖可提取的文字层 |
| 全应用 | 最多 100 份资料、2,000 个片段、200 万个向量数值 |
| 分块 | 约 850 字符、700 字符步长，保留重叠 |
| 每个助手／每次检索 | 最多绑定 6 个库，每次返回最多 5 个来源 |
| 解析 | 独立 Worker、约 192 MB JS 堆限制、45 秒解析超时 |

**扫描版 PDF 需要先 OCR**。不会自动识别图片，不保证复杂表格、分栏的阅读顺序；PDF 页码是 PDF 文件内部页序。没有自动监控原文件变化，文件更新后需重新导入。本轮不含临时文件问答、网页抓取、大型语料库或高级分块配置。

## 三、MCP：配置、连接、授权、确认、执行

MCP 连接和工具都运行在 **Node 服务所在电脑**，不是浏览器所在电脑。浏览器从另一台电脑访问，并不意味着工具会在那台电脑运行。

1. 在运行 Node 的本机，用 `http://localhost:3000` 打开应用，进入「设置 → MCP 工具」。
2. 添加服务器：支持 **stdio** 和 **Streamable HTTP**。
3. stdio 填可执行命令和 JSON 参数数组；环境变量填写 JSON 对象。HTTP 填地址及请求头 JSON 对象。远程 HTTP 地址须使用 HTTPS，本地回环地址允许 HTTP；URL 不得含用户名／密码，请把凭据放入专用环境变量／请求头字段，而不是 URL 查询参数或命令参数。
4. 保存只保存配置，**不会启动程序**。检查内容后手动「连接并发现工具」，再次确认后才启动连接。
5. 编辑助手 →「知识库与工具」，勾选允许该助手使用的具体工具（最多 24 个），保存。
6. 选择支持**原生工具调用**的模型，在对话里提出需要该工具的任务。
7. 当模型申请调用时，聊天里出现服务器、工具名、实际参数和确认卡片。检查后点「允许本次执行」或「拒绝」。允许后执行实际 MCP 工具，将文本结果回传模型并继续回答。

**不会执行模型写在普通文字、代码块或 XML 中的“工具调用”。** 模型不支持原生 tools 协议时，不应期待工具执行；免费服务商是否支持由其实际模型能力决定。

### 安全边界

- MCP 管理、工具授权及执行限服务端本机请求；当前没有远程登录鉴权，不能作为公网多用户服务部署。默认 Node 监听 `127.0.0.1`。
- 每次调用都需一次性确认，90 秒无人确认则拒绝；令牌不写入聊天记录。每次工具执行最多等待 30 秒；一轮对话最多实际执行 4 次，最多 5 次模型请求（留一次最终回答机会）。
- 可以停止等待并发送取消信号，但**无法保证第三方工具立即停止，更不能撤销已经写文件、发请求等副作用**。
- 保存／导入配置不自动连接；重启后必须重新连接。编辑服务器会断开连接并撤销原授权；删除服务器会解除其授权。复制助手不继承 MCP 授权，需重新选择。
- 环境变量／请求头专用凭据字段在界面上遮罩、在 DB 中以 AES-GCM 加密，密钥为 `data/mcp-vault.key`。普通参数、工具结果及聊天内容不属于这个加密保险库。
- **工具授权不是操作系统沙箱**。启动的 MCP 程序本身拥有当前 Node 进程用户的操作系统权限，连接阶段就可能读写文件或联网；务必只连接可信服务器。对不可信程序应另用低权限账号／容器隔离。
- 工具文本结果最多保留约 16,000 字符。暂不处理二进制结果、自动 MCP resources、旧 SSE transport、OAuth 或服务器市场自动安装。

### 无破坏性的连通测试

项目附带测试服务器，仅提供 `echo_note` 回显工具，可先验证链路：

- 传输：stdio
- 命令：`node`（或 Node 可执行文件的完整路径）
- 参数：`["scripts/fixtures/mcp-server.mjs"]`
- 从项目根目录启动 Agent Studio，连接后仅授权 `echo_note`。

这只是本地测试夹具，不是生产业务服务，也不能证明任意第三方 MCP 都兼容。

## 四、备份与网络

- `data/db.json`：设置、聊天、资源配置、资料状态及索引（含向量）。
- `data/knowledge/`：导入的原始文档。
- `data/mcp-vault.key`：MCP 凭据解密密钥。丢失后需重新录入凭据。
- 建议**停止服务后备份整个 data 文件夹**。该目录包含隐私资料、聊天和密钥，应加密保管、限制文件访问权限。
- 「设置 → 备份与恢复」的 JSON 包含索引及 MCP 配置元数据，**不包含原始文档和保险库密钥**。不是完整便携备份：迁移后索引仍可检索，但重新解析需要原文件，凭据也可能需要重新录入。
- 导入含 MCP 配置的 JSON 仅允许在服务端本机进行；导入会关闭现有连接并清空助手的 MCP 授权，不执行任何配置命令。索引进行中会拒绝恢复；恢复后请重启应用，再手动连接及重新授权。
- 普通 HTTP API 增加同站 Origin／Fetch-Site／Host 检查。需要自定义域名时用 `ALLOWED_HOSTS`（逗号分隔）；它**不是身份验证**。
- 如设置 `HOST=0.0.0.0`，只能用于受信网络或开发预览。普通 API 仍无账号鉴权，MCP 仍限制本机。不要直接暴露到互联网，也不要靠反向代理把远程请求伪装成本机来绕过限制。

## 五、实际验证与未验证内容

测试源代码随包提供：

- `npm test`：原协议／代理／命令／助手测试，以及知识库／MCP 核心 **27/27**。
- `npm run test:resource-api`：运行中的服务端 HTTP／SSE 集成 **9/9**。
- `npm run test:resource-ui`：jsdom 管理页面及真实聊天确认、执行、来源与持久化 **17/17**。
- `npm run test:assistant-ui`：原助手与二级话题交互 **26/26**。
- `npm run test:smoke`：原模块回归 **86/86**，无运行时错误。
- `npm run build`：生产前端构建；打包另核对 ZIP 内清单、版本、资产及文件 SHA-256。

上述集成／UI 测试需要先启动本地服务；测试会创建并清理自己的临时记录。建议在独立测试数据目录运行。

验证环境为 Linux 上的 Node 和 jsdom；PDF／DOCX 用真实文件，Embedding／模型使用可控本地 HTTP 上游，MCP 使用真实官方 SDK stdio 和 Streamable HTTP 测试服务器。**尚未在原生 Windows 桌面上验收，也未验证真实付费模型服务、任意第三方 MCP、OCR 或远程身份认证。** Windows 批处理保持 ASCII／CRLF，并做了静态检查及跨平台命令构造测试，但这不能替代原生 Windows 实测。
